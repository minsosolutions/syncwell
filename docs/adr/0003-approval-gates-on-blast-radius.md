# Approval gates on blast radius, and a Run never waits for it

Some of what a Run produces is safe to write unattended and some is not, and the boundary is not the Output kind. An action needs a human's approval when it **crosses the boundary to the Customer** — lands in their inbox, appears in a system they read — or when it **destroys work** a human may care about. Everything internal and reversible proceeds unattended: creating and updating issues inside our own Linear project is working material, and gating it would put a click between the Run and every line it writes. Deleting an issue is gated by the same rule that gates an email, without either being named in a list.

A Run does not wait for the decision. It writes the ungated Outputs and emits the rest as **Proposals** into the Customer Directory; the admin UI is where they are approved, and approval applies them there and then, through the same writer path the Run uses. Blocking a Run on a human's attention was the alternative, and it ties the lifetime of a `claude -p` sub-process to someone reading their screen — an approval that arrives tomorrow is a normal outcome, not a failure.

What the human approves is the artifact, byte for byte: this subject, this body, these recipients. Approving a decision and rendering the message afterwards would put the model's wording past the gate, which is the one thing the gate exists to prevent. Approval therefore binds to a hash of the artifact, and a Proposal superseded after approval but before application drops back to pending rather than sending content nobody read.

Recipients are derived in Go, not proposed by the model: an address must already appear in a Source Record collected for that Customer, and must match that Customer's configured domains. A model that picks who to email can pick the wrong Customer's contact, which is the leak that ADR-0001 spends the whole Routing Rule preventing one step earlier.

Proposals and their rejections live in the Customer Directory beside the Manifest, which means an Agent sees its own pending and suppressed Proposals on the next Run. That is deliberate: "you already proposed writing to them about this" is context worth having, unlike Drift reconciliation, which is our bookkeeping and stays out. A rejection suppresses that action for that finding indefinitely and is reversible in one click, following the same principle as Stewardship in ADR-0002: a human gesture is obeyed and never silently expires. Applied actions are recorded in the Manifest even when the Output has no identity to steward, because "have we already told them?" is asked by every later Run, and because an audit trail of approvals is half the reason to have a gate.
